================================================================================
  glTF / GLB 一括エクスポートツール  使い方ガイド
================================================================================

作成日 : 2026年6/26
更新日 : 2026年9/19（出力先を毎回ダイアログで選ぶ方式に変更・出力後の検査を追加）
　　　　 2026年10/21（SoundWave を .wav で出せるようにした）
対応UE : Unreal Engine 5.7

概要　 : UE5でアセットをいちいち一つずつ指定してエクスポートするのが大変だったので
　　　　 一括でエクスポートできるように作成しました。
　　　　 基本的な動作は大丈夫だと思いますが、問題があった場合は自己責任でお願いします。
　　　　 怖い場合はpyファイルをＡＩに読み込ませて確認してもらうとかでも大丈夫です。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  このツールでできること
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Content Browser で選択したアセットを一括で glTF / GLB ファイルへエクスポートします。

対応アセット:
  ・StaticMesh（スタティックメッシュ）
  ・SkeletalMesh（スケルタルメッシュ）
  ・AnimSequence（アニメーションシーケンス）
  ・SoundWave（音声）… これだけは glTF ではなく .wav で出ます

モデルと音声を混ぜて選んでも、それぞれの形式で一緒に出せます。

対応していないアセット（テクスチャ、マテリアル、Blueprint 等）は
自動でスキップされます。エラーにはなりません。

SoundCue は複数の音を組み合わせる仕組みで、音声ファイルそのものではないので出せません。
選んだ場合は Output Log に名前が出てスキップされます。
中で使っている SoundWave の方を選んでください。

出力先は実行するたびにダイアログで選びます。
勝手にどこかへ出力することはありません。

エクスポートしたあと、出力したファイルを開いて中身を確認し、
Output Log に報告します（ボーン数・アニメーション名・キー数など）。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  使用前の準備
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【必須】以下の UE プラグインが有効になっていることを確認してください。

  1. Python Editor Script Plugin
  2. glTF Exporter Plugin

確認方法:
  UE エディタ上部メニュー → Edit → Plugins
  検索欄に「Python」「glTF」と入力して、それぞれ有効（チェック済み）か確認


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  スクリプトの設定
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

出力先はダイアログで選ぶので設定不要です。
それ以外の項目はスクリプト上部にまとまっています。

------------------------------------------------------------

■ EXPORT_GLB（出力形式の切り替え）

  EXPORT_GLB = False   → .gltf 形式で出力（デフォルト）
  EXPORT_GLB = True    → .glb  形式で出力

  .gltf と .glb の違い:

    .gltf  テキストベースのJSON形式。
           .gltf ファイルのほかに .bin ファイルとテクスチャ画像が
           同じフォルダに別々に出力される。
           中身を確認・編集しやすい。

    .glb   バイナリ形式。
           メッシュ・テクスチャ・アニメーションがすべて1ファイルにまとまる。
           配布や受け渡しに便利。

------------------------------------------------------------

■ FLATTEN_OUTPUT（出力先の中での置き方）

  FLATTEN_OUTPUT = True    選んだフォルダの直下へ平置き（デフォルト）
  FLATTEN_OUTPUT = False   UE のフォルダ構造をそのまま再現する

  ※ エンジンへ入れる場合は True にしてください。
    エンジンはアニメーションフォルダの「直下だけ」を見ます。
    False のままだと
      選んだフォルダ/Characters/Muriel/Anims/Idle_Loop.gltf
    のように掘られて、エンジンから発見されません。

------------------------------------------------------------

■ EXPORT_PREVIEW_MESH（アニメーション出力時の設定）

  EXPORT_PREVIEW_MESH = True    スケルトン＋アニメーション＋プレビューメッシュ
  EXPORT_PREVIEW_MESH = False   スケルトン＋アニメーションのみ（デフォルト）

  AnimSequence を出力する場合のみ影響します。
  StaticMesh / SkeletalMesh の出力には影響しません。

  エンジンへ入れる用途では False のままで大丈夫です。
  ボーン情報はメッシュ無しでも含まれます。
  単体で別ソフトに読ませて見た目を確認したいときだけ True にしてください。

------------------------------------------------------------

■ INSPECT_AFTER_EXPORT（出力後の検査）

  True（デフォルト）にしておくと、出力したファイルを開いて中身を
  Output Log に報告します。切りたい場合だけ False にしてください。

------------------------------------------------------------

■ REFERENCE_MODEL（照合用モデル）

  空（デフォルト）にしておくと、選んだ出力先の親フォルダにある .glb を
  自動で探して、それと照合します。

  例: 出力先に  .../NewMuriel/Animations  を選ぶと
      親フォルダの  .../NewMuriel/Muriel_GDC.glb  を自動で見つけます。

  親フォルダに .glb が複数ある場合は、どれか分からないので照合しません。
  その場合だけフルパスを書いてください。

    REFERENCE_MODEL = r"D:\...\Muriel_GDC.glb"

------------------------------------------------------------

  スクリプトの置き場所
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

どこに置いても動きますが、以下の場所が便利です。

  UE5プロジェクトフォルダ/Content/Python/batch_export_gltf.py

この場所に置くと、実行時にファイル名だけで呼び出せます（フルパス不要）。

  例: py "batch_export_gltf.py"

※ Content/Python フォルダを新しく作った場合は、UE を再起動しないと
  認識されません（起動時に一度だけ検索パスへ追加されるため）。
  置いただけでは自動実行もされません。必ず下の手順で呼び出してください。

僕の場合は普通にツールみたいなフォルダに入れておいて
そこの絶対パスを保存した状態で使用してます


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  使い方（手順）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. UE5の Content Browser でエクスポートしたいアセットを選択する

     Ctrl + クリック  → 複数を個別に選択
     Shift + クリック → 範囲選択
     Ctrl + A         → フォルダ内を全選択

2. Output Log を開く

     UE エディタ上部メニュー → Window → Output Log（日本語だと「出力ログ」）

3. Output Log の下部にある入力欄にコマンドを入力して Enter

     【Content/Python/ に置いた場合】
     py "batch_export_gltf.py"

     【それ以外の場所に置いた場合（フルパスを指定）】
     py "C:\Users\自分の名前\Desktop\batch_export_gltf.py"

   ※ Tools メニュー → Execute Python Script... からファイルを選んでも実行できます。

4. フォルダ選択ダイアログが出るので、出力先を選ぶ

     エクスプローラーと同じ見た目のダイアログです。
     上部のアドレス欄にパスを直接貼り付けることもできます。

     ・前回選んだ場所から開きます
     ・キャンセルすると何も出力せずに終了します
     ・UE の裏に隠れて出てくることがあります。反応が無くなったように
       見えたら Alt + Tab で探してください

5. 進捗バーが表示されてエクスポートが始まる
   現在処理中のアセット名が進捗バーに表示されます。
   途中でやめたい場合は「Cancel」ボタンを押してください。

6. 完了後に結果ダイアログが表示される

     Finished

     Success : 8
     Failed  : 0
     Skipped : 1（対応外アセット）

7. Output Log で検査結果を確認する（次の次の節）


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  エンジンへアニメーションを追加する手順（Valkyra）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Content Browser で AnimSequence を選択して実行

2. 出力先に  Assets/Models/Enemy/NewMuriel/Animations  を選ぶ

3. Output Log で「ボーン名はモデルと完全に一致しています」を確認

4. エンジンを起動する。以上。

   Animations/ に置かれたファイルは自動で読み込まれます。
   Valkyra.model.json を編集する必要はありません。
   キャッシュ（Valkyra.model.cereal）もフォルダの更新を見て自動で作り直されます。

5. Sequencer で使う場合は、Output Log に出た「アニメ名」を
   targetAnimName に書きます。ファイル名ではなくこちらです。

     [glTF Export]     アニメ名 ConsecratedGround_Cast_0  ...
                              ^^^^^^^^^^^^^^^^^^^^^^^^ これを使う

   UE の glTF 書き出しはアニメーション名の末尾に _0 を付けます。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  エンジンへ効果音を追加する手順
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. Content Browser で SoundWave を選択して実行

2. 出力先に  Assets/Audio/SE/（置きたいフォルダ）  を選ぶ

3. 下の命名規則で名前を付ける。登録はいりません
   エンジンを起動し直すと、ファイル名がそのままイベント名になります
     Assets/Audio/SE/Player/SE_PlayerSlashLight.mp3  →  sfx:/SE_PlayerSlashLight
     Assets/Audio/BGM/GameBGM.mp3                    →  bgm:/GameBGM
   ※ ファイル名は英数字にしてください（日本語の名前は読み込まれません）
   ※ 別のフォルダでも、同じファイル名は1つしか使えません

4. 鳴らしたい場所で、そのイベント名を指定する
   （アニメのシーケンサーなら「+ Sound」で置いて、音の欄から選ぶ）

エンジンの起動ログに  サウンド読み込み: 成功N / スキップ0  と出れば読み込めています。
スキップが増えていたら、その上の警告に理由（日本語の名前・名前の重複・壊れたファイル）が出ています。

音声には出力後の検査（ボーン・キー数）はありません。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  効果音の命名規則とフォルダ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

名前:  SE_<だれの><なにの音>       （VFX_BossLeapImpact と同じ形）
  だれの     … Player / Boss / UI など。フォルダ名と同じにする
  なにの音   … 鳴る場面を PascalCase で。素材の中身（Whoosh・Ping など）ではなく用途で付ける
                 → 後で別の素材に差し替えても、名前と置いた場所を直さずに済む
  例: SE_PlayerSlashLight（軽い斬撃）/ SE_PlayerHurt（プレイヤーが攻撃を受けた）
      SE_BossLeapImpact（ボスの跳躍攻撃の着地）/ SE_UIConfirm（決定）
  Hurt は「そのキャラが攻撃を受けた音」。ボスに当てた音は SE_BossHurt

フォルダ:
  Assets/Audio/SE/Player   プレイヤーの動き・攻撃・被弾
  Assets/Audio/SE/Boss     ボスの動き・攻撃・被弾
  Assets/Audio/SE/UI       メニュー・画面切り替え
  Assets/Audio/SE/Unused   使わない候補の置き場。素材の元の名前のままでよい
                           エンジンは読まず、Pak にも入らない
                           使うときは上の規則で名前を付けて、用途のフォルダへ移す



━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  出力フォルダの構造について
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

FLATTEN_OUTPUT の設定で変わります。

【FLATTEN_OUTPUT = True】アセット名だけを使って、選んだフォルダの直下に置かれます。

  UE 内のパス:
    /Game/Characters/Muriel/Anims/Idle_Loop

  出力結果:
    選んだフォルダ\Idle_Loop.gltf

【FLATTEN_OUTPUT = False】UE 内のフォルダ構造がそのまま再現されます。

  UE 内のパス:
    /Game/Characters/Hero/SK_Hero

  出力結果:
    選んだフォルダ\Characters\Hero\SK_Hero.gltf

同名ファイルが既に存在する場合は自動で上書きされます。

平置きでは、UE 内の別フォルダにある同名アセットが同じファイルへ書かれて
片方が消えてしまいます。これはエクスポートを始める前に検出して中断します。

  [glTF Export] 出力ファイル名が衝突しています。中断しました。
  [glTF Export]   Idle_Loop.gltf <- /Game/A/Idle_Loop, /Game/B/Idle_Loop

この場合は UE 側でアセット名を変えてください。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  Output Log の見方
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

処理の経過は Output Log に以下の形式で出力されます。

  [glTF Export] Export Start
  [glTF Export] 出力先    : ...\NewMuriel\Animations
  [glTF Export] 出力形式  : .gltf （平置き）
  [glTF Export] 対象件数  : 8
  [glTF Export] 照合用モデルを自動で見つけました: ...\Muriel_GDC.glb
  [glTF Export] 照合用モデル: Muriel_GDC.glb （ボーン 117 本）
  [glTF Export] Export ConsecratedGround_Cast  ->  ...\ConsecratedGround_Cast.gltf
  [glTF Export]     ノード 118 個（名前あり 117 本）
  [glTF Export]     アニメ名 ConsecratedGround_Cast_0  チャンネル 351 本  [68キー×351本]
  [glTF Export]     ボーン名はモデルと完全に一致しています（117 本）
  [glTF Export] Finished
  [glTF Export] Success : 8
  [glTF Export] Failed  : 0

Output Log で「glTF Export」と検索するとこのツールのログだけ絞り込めます。

------------------------------------------------------------

■ 検査結果の読み方

  ノード 118 個（名前あり 117 本）
      アニメーションに含まれるボーンの数です。
      名前の無いノードが1つあるのは glTF のルートノードで、正常です。

  チャンネル 351 本  [68キー×351本]
      「何本のボーンが」「何キーで」動くかです。
      全部同じキー数ならきれいに出ています。

  キーが2本以下に潰れたチャンネルが NNN 本あります
      ★ これが出たら、そのボーンは再生しても動きません。
      往復運動（翼が開いて閉じる等）は始点と終点が同じ値になるため、
      キーを間引く処理が入ると2本に潰れて完全に静止します。
      エディタ上では正常に見えるので、このログでしか気付けません。

  ボーン名はモデルと完全に一致しています
      そのまま使えます。

  モデルに無いボーンが NN / NNN 本あります
      一部のボーンだけ動きません。UE 側の書き出し設定か、
      スケルトンが変わっていないか確認してください。

  ボーン名がモデルと一つも一致しません
      別のキャラクターのアニメーションを出している可能性があります。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  よくある質問
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Q. スクリプトを Content/Python に置いたのに何も起こらない
A. 置いただけでは実行されません。自動実行されるのは init_unreal.py という
   名前のファイルだけです。上の手順3のコマンドで呼び出してください。
   フォルダを新しく作った場合は UE の再起動も必要です。

Q. 「py」と打っても Command not recognized と言われる
A. Python Editor Script Plugin が無効です。
   Edit → Plugins から有効にして UE を再起動してください。

Q. フォルダ選択ダイアログが出てこない
A. UE の裏に隠れている可能性があります。Alt + Tab で探してください。
   Output Log に「フォルダ選択ダイアログを開けませんでした」と出ている場合は
   本当に開けていません。その場合は何も出力せずに終了します。

Q. 「テクスチャをビルドしています」というログが大量に出るがエラーか？
A. エラーではありません。
   glTF Exporter がマテリアルをテクスチャへ変換する正常な処理ログです。

Q. エンジンに入れたのにアニメーションが増えない
A. まず出力先を確認してください。FLATTEN_OUTPUT = False のままだと
   サブフォルダへ掘られてエンジンから見えません。
   エンジンが見るのは Animations/ の直下だけです。

Q. .gltf を移動したら読めなくなった
A. .gltf は .bin とセットです。必ず2つ一緒に動かしてください。
   .bin が無い場合は検査ログにエラーが出ます。

Q. アニメーションを出力したが別ソフトで再生できない
A. EXPORT_PREVIEW_MESH = True にすると
   プレビューメッシュ（スケルトン込み）が付いた状態で出力されます。
   単体での再生確認にはこちらを推奨します。
   ただしエンジンへ入れる用途では False のままにしてください。

Q. StaticMesh を出力したが .gltf のほかに大量のファイルが出た
A. .gltf 形式の仕様です。.bin（バイナリデータ）とテクスチャ画像が
   同じフォルダに別々に出力されます。
   1ファイルにまとめたい場合は EXPORT_GLB = True にしてください。

Q. 選択したアセットが Skipped（スキップ）されてしまう
A. 対応しているのは StaticMesh / SkeletalMesh / AnimSequence / SoundWave のみです。
   Texture や Material、Blueprint、SoundCue などは対応外のためスキップされます。

Q. last_output_dir.txt というファイルができた

   消しても問題ありません（次回はダイアログが初期位置から開くだけです）。
