================================================================================
  テクスチャ DDS 変換ツール  使い方・仕様
================================================================================

作成日 : 2026年8/19（ツール本体）
説明書 : 2026年10/27

概要　 : モデルのテクスチャ（PNG / JPEG）を、GPU がそのまま読める DDS に
　　　　 まとめて変換するツールです。
　　　　 中身は Microsoft の texconv.exe を順番に呼んでいるだけです。

  同封ファイル
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Tools\batツール\テクスチャDDS変換.bat      … ダブルクリック用の起動役
  Tools\batツール\TextureToDDS.ps1           … 本体（処理はすべてこちら）
  Tools\batツール\テクスチャDDS変換_使い方.txt … この説明書
  Tools\Texconv\texconv.exe                  … 実際に変換する外部ツール

  ps1 は texconv.exe を「Tools\Texconv\texconv.exe」の場所で探します。
  フォルダの位置を変えると動かなくなるので、動かすときは ps1 の
  $texconv の行も直してください。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  なぜ DDS にするのか
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

PNG / JPEG のままだと、読み込むたびに画像を展開（デコード）してから
GPU へ送るので時間がかかります。
4K のテクスチャが数十枚あると、Debug ビルドでシーンの読み込みに
60 秒近くかかっていました（実測）。

DDS は GPU 用の圧縮形式なので、ほぼそのまま GPU へ送れます。
・読み込みが速くなる
・VRAM の使用量が減る（BC7 圧縮）
・ミップマップが付くので、遠くの物のちらつきが減り描画も軽くなる


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  エンジン側の仕組み（なぜ置くだけで効くのか）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

モデルを読み込むとき、テクスチャのパスの拡張子を .dds に変えたファイルが
同じフォルダにあれば、そちらを使います。

  例）モデルが Textures\Rock_Base.png を指している
      → Textures\Rock_Base.dds があれば、そちらを読む
      → 無ければ今まで通り Rock_Base.png を読む

  該当箇所: Source\Engine\Graphics\Resource\ModelResource.cpp
            「同じ名前の .dds があれば、そちらを使う」のコメントの所

このため、
・.glb / .gltf / .cereal を作り直す必要はありません
・元の PNG / JPEG は消さずに残しておきます（DDS を作り直すときの元になる）
・元に戻したいときは、作った .dds を消すだけで PNG / JPEG 読み込みに戻ります


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  使い方 1：bat をダブルクリック（普段はこれ）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Tools\batツール\テクスチャDDS変換.bat をダブルクリックするだけです。

  このときの設定（固定）:
    対象       : Assets\Models 以下すべて
    除外       : 「Test」という名前のフォルダの中
    長辺上限   : 2048 px（これより大きい画像は縮小）
    既存の.dds : 飛ばす（作り直さない）

  既にある .dds は飛ばすので、何回実行しても
  「新しく増えたテクスチャだけ」が変換されます。
  モデルを追加したら、とりあえずこれを 1 回実行すれば OK です。

  終わると件数と容量（元 → DDS）が表示され、キー入力待ちで止まります。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  使い方 2：PowerShell から細かく指定
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  特定のフォルダだけ、解像度を変えたい、作り直したい、などのとき。
  リポジトリのルート（ProgressCore-Engine フォルダ）で実行します。

    powershell -ExecutionPolicy Bypass -File .\Tools\batツール\TextureToDDS.ps1 （オプション）

  ※ -ExecutionPolicy Bypass は「このスクリプトの実行を許可する」指定です。
     付けないと「スクリプトの実行が無効」で止まることがあります。

  オプション一覧:

    -Root <フォルダ>     対象にするフォルダ（リポジトリルートからの相対パス）
                         既定: Assets\Models
                         例) -Root Assets\Models\Props

    -MaxSize <数>        長辺の上限ピクセル数。0 で縮小しない
                         既定: 2048
                         例) -MaxSize 1024   -MaxSize 0

    -Force               既に .dds があっても作り直す
                         （元の画像を描き直したときに使う）

    -DryRun              変換はせず、対象の一覧とサイズだけ表示する
                         迷ったらまずこれを付けて確認する

    -ExcludeDirs @(...)  飛ばすフォルダ名の一覧
                         既定: @('Test')
                         例) -ExcludeDirs @()        … 除外なし（Test も変換）
                             -ExcludeDirs @('Test','Player')

  よく使う組み合わせ:

    新しく入れたモデルのフォルダだけ、まず確認する
      ... -Root Assets\Models\Props -DryRun

    確認できたので変換する
      ... -Root Assets\Models\Props

    元画像を差し替えたので、そのフォルダを作り直す
      ... -Root Assets\Models\Props -Force


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  仕様（処理の中身）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. 対象を集める
   -Root の中を下の階層まですべて探し、.png / .jpg / .jpeg を集める。
   パスの途中に -ExcludeDirs の名前のフォルダがあるものは外す。
   （フォルダ名が完全に一致したときだけ。「TestScene」は「Test」に当たらない）

2. 1 枚ずつ変換する
   ・同じ名前の .dds が既にあれば飛ばす（-Force のときは作り直す）
   ・画像の幅と高さを読む
   ・長辺が -MaxSize を超えていれば、縦横比を保ったまま縮小する
     BC7 は 4×4 ピクセル単位で圧縮するので、縦横とも 4 の倍数に丸める
   ・texconv で変換する

       形式       : BC7_UNORM（すべてのテクスチャ共通）
       ミップ     : 最小サイズまで全段作る
       出力先     : 元の画像と同じフォルダ
       ファイル名 : 元と同じ名前で拡張子だけ .dds

3. 結果を表示する
   変換した枚数・飛ばした枚数・失敗した枚数・容量の変化。

元の画像を書き換えたり消したりすることはありません（追加のみ）。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  色の扱い（BC7_UNORM で統一している理由）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【触らないこと】BaseColor だけ BC7_UNORM_SRGB にする、などはしないでください。

このエンジンは sRGB の変換をどこでもしていません。
（バックバッファは R8G8B8A8_UNORM、シェーダーにもガンマ補正が無い）
テクスチャの値をそのまま使って、そのまま画面に出す作りで、
アートもその見え方で調整しています。

ここで BaseColor を _SRGB にすると、GPU が読み込むときに勝手に暗くする変換が入り、
色が一段沈んで赤茶けた「錆びたような」色になります（実際になりました）。

BC7_UNORM なら PNG を読んだときと値の解釈がまったく同じなので、
見た目は変わらず、圧縮とミップだけが付きます。

将来エンジンを sRGB 対応にするなら、バックバッファと
BaseColor / Emissive を同時に _SRGB にすること。片方だけだと見た目が壊れます。
（詳しい経緯は TextureToDDS.ps1 の「色空間について」のコメント）


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  注意点
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

■ 元の画像を描き直したら -Force が必要
  .dds が残っているとエンジンは古い .dds を使い続けます。
  「画像を直したのに見た目が変わらない」ときは、まずこれを疑ってください。
  （そのフォルダだけ -Root で指定して -Force を付ける）

■ .glb の中に埋め込まれた画像は変換されない
  フォルダに PNG / JPEG として出ているものだけが対象です。
  UE5 エクスポートツールで出したモデルは Textures フォルダに画像が出るので大丈夫です。

■ Test フォルダは既定で除外
  Assets\Models\Test は Sponza などのサンプル置き場で、ゲームでは使っていません。
  ファイル名がハッシュ（10381718147657362067.jpg のような名前）で、
  何のテクスチャか名前から判断できないため外しています。
  変換したいときは -ExcludeDirs @() を付けます。

■ bat に日本語を書かない
  cmd.exe は日本語（マルチバイト文字）を含む bat をうまく読めないことがあります。
  そのため bat は英語だけにして、日本語の説明は ps1 とこのファイルに書いています。
  bat を編集するときも英数字だけにしてください。

■ 2048 px に縮小される
  bat から実行すると 4K のテクスチャも 2048 に縮みます。
  近くで大きく映るもので画質が足りないときは、そのフォルダだけ
  -MaxSize 0 -Force で作り直してください。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  うまくいかないとき
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

「texconv.exe が見つかりません」
  → Tools\Texconv\texconv.exe があるか確認。

「変換対象フォルダが見つかりません」
  → -Root のパスを確認。リポジトリルートからの相対パスで書く
     （Assets\Models\Props のように。先頭に \ は付けない）。

「画像を読めませんでした」
  → 画像が壊れているか、拡張子と中身が違う（.png なのに中身が別形式など）。
     その画像だけ飛ばして続きは変換されます。

「変換に失敗しました (exit=...)」
  → texconv がエラーを出した。そのファイルだけを手で変換してみると原因が分かります。
       .\Tools\Texconv\texconv.exe -f BC7_UNORM -m 0 -o （出力フォルダ） （画像）

「スクリプトの実行が無効になっているため…」
  → PowerShell から直接 .ps1 を実行したとき。
     powershell -ExecutionPolicy Bypass -File ... の形で実行する（bat は対応済み）。

見た目が変わった・色がおかしい
  → まず作った .dds を消して PNG に戻し、元と比べる。
     色が違うなら「色の扱い」の節を確認。
