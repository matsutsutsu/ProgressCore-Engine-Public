================================================================================
  Data.pak 作成ツール  使い方・仕様
================================================================================

作成日 : 2026年10/27
更新日 : 2026年10/27（目次と中身を XOR で暗号化するようにした）

概要　 : Assets 以下のファイルを 1 つのアーカイブ（Data.pak）にまとめるツールです。
　　　　 外部に exe を配るとき、素材を PNG / glb などのまま並べずに済むようにします
　　　　 （Fab の Standard License は「素材単体での配布」と「抜き出し」を禁じているため）。
　　　　 目次（ファイル名）と中身は暗号化してあるので、テキストエディタで開いても
　　　　 ファイル名は読めず、PNG などを切り出すこともできません。

  Tools\Pak作成ツール\Pak作成.bat   … ダブルクリック用の起動役
  Tools\Pak作成ツール\make_pak.py   … 本体（処理はすべてこちら）
  Tools\Pak作成ツール\使い方.txt    … この説明書

  読む側（エンジン）: Source\Engine\Platform\Core\FileSystem.cpp
  書式を変えるときは、make_pak.py と FileSystem.cpp の両方を直すこと。

  必要なもの: Python 3（python コマンドで起動できること）


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  使い方
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. 先に Debug か Development でゲームを一度起動しておく
   モデルのキャッシュ（.cereal）は、起動したときに最新に作り直されます。
   pak にはその時点の .cereal がそのまま入るので、古いまま作ると
   「アニメーションを足したのに配布版に入っていない」ことになります。

2. Pak作成.bat をダブルクリック
   Build\Pak\Data.pak に書き出されます（数百 MB）。暗号化に 1 分ほどかかります。
   Build\Pak\ は .gitignore に入っているのでコミットされません。

   PowerShell から実行する場合:
     python Tools\Pak作成ツール\make_pak.py              … 作る（暗号化あり）
     python Tools\Pak作成ツール\make_pak.py --dry-run    … 作らずに集計だけ出す
     python Tools\Pak作成ツール\make_pak.py --list       … 入れるファイルを全部出す
     python Tools\Pak作成ツール\make_pak.py --no-encrypt … 暗号化しないで作る（中身を目で確かめたいとき）
     python Tools\Pak作成ツール\make_pak.py --out D:\x\Data.pak  … 書き出し先を変える

   暗号化あり・なしのどちらで作っても、エンジンはヘッダの flags を見て自動で読み分けます。

3. Shipping ビルドの exe と同じフォルダ（起動したときの作業フォルダ）に Data.pak を置く


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  エンジン側の動き
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

・Shipping 構成だけ、起動時に作業フォルダの Data.pak を開きます
  （Framework のコンストラクタ → FileSystem::Initialize → Mount）。
  Debug / Development は開きません。今まで通り Assets フォルダから読みます。

・ファイルを読むときは「Data.pak の中 → ディスク」の順に探します。
  pak に入っていない物（遊んだ人の設定 Saved\ など）はディスクから読みます。

・Data.pak が無い・壊れているときは警告を出して、ディスクから読みます。
  開発フォルダで Shipping を起動したとき（Assets がある）はそのまま動きます。

・パスは表記を揃えてから探します。\ と / の違い、. と ..、英字の大文字小文字は
  区別しません。日本語のファイル名もそのまま使えます。

・モデル定義（Muriel.model.json）のキャッシュが pak の中にあるときは、
  更新時刻を比べずにそのまま使います（pak の中には更新時刻が無いため）。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  入れない物
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Assets\Models\Test\ の中           … Sponza などのサンプル。ゲームでは使っていない
  Assets\Fonts\ArialUni.ttf          … エディタ（ImGui）専用。配布物に同梱できないフォント
  Assets\Models\ 以下の画像で、
    同じ名前の .dds があるもの       … エンジンは .dds の方を読むので、元の画像は使われない
  .glb / .gltf / .bin で、
    同じ名前の .cereal があるもの    … エンジンは .cereal の方を読むので、元のモデルは使われない

  ルールを変えるときは make_pak.py 先頭の EXCLUDE_DIRS などを編集します。

  【注意】Assets\Models 以外の画像（UI など）は、コードが .png を名指しで読むので、
  .dds があっても外しません。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  書式（make_pak.py と FileSystem.cpp で同じ）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  数値はすべてリトルエンディアン。

  [ヘッダ] 16 バイト
    "PCPK"              4 バイト   識別子
    version             u32        いまは 1
    entryCount          u32        ファイル数
    flags               u32        1 = 暗号化あり / 0 = 暗号化なし

  [目次] entryCount 回くり返し
    pathLength          u16        path のバイト数
    path                UTF-8      例: Assets/Models/Props/SM_Rock_21.cereal
                                   （/ 区切り。大文字小文字は元のまま）
    offset              u64        中身の位置（アーカイブの先頭から）
    size                u64        中身のバイト数

  [中身]
    各ファイルのバイト列を目次の順に並べたもの

  上の目次と中身の数値・文字列は「暗号化する前」の値です。
  暗号化ありのときは、ヘッダより後ろが次の暗号化を掛けた状態で入っています。


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  暗号化のしくみ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ヘッダ（先頭 16 バイト）より後ろの全バイトに、乱数列を XOR しています。
  XOR は同じ値をもう一度掛けると元に戻るので、エンジンは読んだ後に同じ乱数列を掛けて戻します。

  乱数列の作り方:
    位置 p（アーカイブ先頭から何バイト目か）のバイトには、
    splitmix64( KEY ^ (p ÷ 8) ) の (p % 8) 番目のバイトを XOR する。

  ・乱数列は「位置」だけで決まるので、どのファイルを読むときも、
    そのファイルの位置からその場で乱数列を作って戻せる（先頭から順に読む必要がない）。
  ・8 バイトごとに違う値になるので、同じ鍵を繰り返し掛けたときのように
    「0 が並んだ所に鍵が浮き出る」ことがない。

  KEY は make_pak.py の KEY と FileSystem.cpp の kArchiveKey の 2 か所に書いてあります。
  変えるときは必ず両方を同じ値にしてください。違うと、エンジンが目次を読めずに起動できません。

  【限界】鍵は exe の中に入っているので、exe を解析されれば破られます。
  目的は「素材を手軽に取り出せないようにすること」で、本格的な暗号ではありません。
  また、リポジトリを公開する場合は make_pak.py の KEY も見えてしまう点に注意してください。

  動作確認のしかた
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Assets を一切見られない状態で起動すると、pak だけで動くかを確かめられます。
  Build\Pak\ には Data.pak しか無いので、そこを作業フォルダにして Shipping の exe を起動します。

    Start-Process Build\bin\x64\Release\OVERCLEAVE.exe -WorkingDirectory Build\Pak

  Shipping はエラーが出たときだけ Logs\Engine.log を作ります。
  遊んだあとに Build\Pak\Logs\Engine.log が無ければ、エラーは出ていません。

  うまくいかないとき
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

配布版がすぐ終わる・何も表示されない（Logs\Engine.log に「アーカイブの目次が壊れています」）
  → make_pak.py の KEY と FileSystem.cpp の kArchiveKey が違っていないか確認する。
     エンジンを作り直した後は、pak も作り直す。

「大文字小文字だけが違うファイルがあります」
  → エンジンは大文字小文字を区別せずに探すので、どちらかの名前を変える。

「python が見つかりません」
  → Python 3 を入れて、python コマンドが通るようにする。

配布版で一部のモデルやテクスチャが出ない
  → --list で入っているか確認する。外すルールに当たっていないか、
     コードがそのファイルを名指しで読んでいないか（.png を直接読むなど）を見る。

配布版でアニメーションが古い
  → 手順 1（Debug で一度起動してキャッシュを作り直す）をしてから pak を作り直す。
